# Everyday Cool Arcade

A standalone desktop package containing **every game in the Everyday Cool
collection, with the lessons attached** — and nothing else. Where the main
Everyday Cool app is the whole workshop, the Arcade is just the games shelf:
an interface of game cards, a Play button for each game, and a 📖 Lesson
button wherever a lesson exists, so the front door (play) and the back door
(the physics, the math, and how the game is built) travel together. It is
the kind of thing a teacher can install, try — Gravity Golf has a way of
warming up neurons — and justify: the lessons are right there in the package.

with it). Room pages with interactive benches and quizzes are workshops,
not standalone games, and are not included.

## Layout

- `interface/index.html` — the arcade shelf (the app's front page).
- `dist/` — the assembled frontend the Tauri shell serves. Generated by
  the sync script; committed so the tag builds have it.
- `dist/games/<slug>/` — one folder per game: the game file and its
  lesson file side by side, so the relative links between them
  (including the in-game 📖 lesson pop-ups) work unchanged. Links from
  games and lessons back to their home rooms do not resolve inside the
  package — the full workshops live on the web, and the interface's
  footer carries the address.
- `tools/games.manifest` — the game inventory (slug, source project,
  game file, lesson file, support files).
- `tools/sync-dist.sh` — re-assembles `dist/` from a collection checkout.
- `src-tauri/` — a minimal Tauri v2 shell: one window, no profiles, no
  splash. Its one deliberate behaviour, borrowed from the main app, is
  sending outside links (a lesson's Wikipedia link, say) to the system
  browser instead of navigating the arcade window away — the window has
  no back button, and a lesson link should never strand a player.

## Re-syncing after the collection changes

```sh
tools/sync-dist.sh ../everyday-cool   # or any path to a collection checkout
```

Then bump the version in `package.json` and
`src-tauri/tauri.conf.json`, update the counts in
`interface/index.html` (hero pill), commit, and tag `vX.Y.Z`. The tag
fires the build workflow, which attaches the Windows setup .exe, the
.msi, and the macOS .dmg to the GitHub release.

## Building

CI does it: push a `v*` tag and `.github/workflows/build.yml` builds
Windows and macOS bundles and attaches them to the release. Locally:
`npm install`, sync the dist, then `npx tauri build`.
